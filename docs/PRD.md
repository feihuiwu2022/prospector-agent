# 拾品 · Agent 选品研究工作台 PRD

**版本：** V2.0（四层结构重写）  
**日期：** 2026-11-15  
**状态：** 实施稿  
**定位：** 日本市场 · 中国供应链。Agent 找品，人审核结果。

---

## 1. 一句话与主线

**人定策略，Agent 找品，人审核。** 人不再负责“找商品”，只负责三件事：选切入策略、判断 Agent 的证据够不够、决定是否投入。

产品按四层组织，每层只解决一件事，层与层之间是单向依赖：

```
L1 策略层  四大切入策略           → 定义 Agent 去哪一类需求里找货
  ↓
L2 流程层  六步落地流程           → 定义 Agent 按什么顺序推进、在哪一步停下等人
  ↓
L3 证据层  数据源与授权边界       → 定义每条结论背后的来源、时效与可信度
  ↓
L4 决策层  人工审核门与利润模型   → 定义人怎么批注、怎么算账、怎么决定是否小测
```

界面自上而下就是这四层：策略卡（层 1）→ 流程导轨（层 2）→ 对话与候选（层 3）→ 审核动作与利润模型（层 4）。人任何时候都能从当前候选回看它的策略、流程状态与来源。

**Agent 不做的事：** 不自动下单、付款、询价、上架、改库存；不在证据不足时给“确定的利润”；不把短视频热度当销量。

---

## 2. 产品原则

1. **默认 Agent 找商品。** 常规路径是“选策略 → Agent 搜索 → 审核候选”，不要求用户先有商品名。
2. **策略是研究框架，不是结论。** 每条策略卡必须显示切入方向与线索来源，并明确它不等于机会保证。
3. **事实、搜索摘要、模型推断、用户假设分开展示。** 每个结论尽量带来源链接、采集时间与数据边界。
4. **缺数据就停在原地。** 流程状态如实显示“已完成 / 部分完成 / 待补数据 / 阻塞”，不用推测填补。
5. **审核留痕。** 人对候选的动作与理由进入本地记录，淘汰必须写原因，理由可复用于下一轮发现。
6. **四项判断保持独立。** 机会潜力、资源匹配度、风险水平、结论置信度各自打分，不合并成总分。

## 3. L1 策略层：四大选品切入策略

策略是页面的第一层，也是 Agent 的检索框架。切换策略会改变 Agent 的搜索语言、线索来源与候选卡上的“策略契合度”描述。

| 策略 | 核心问题 | Agent 的切入方向 | 线索来源 | 典型风险 |
|---|---|---|---|---|
| **A 痛点解决型** | 现有商品哪里反复被抱怨？ | 差评主题、清洗/耐用/收纳/安装等使用缺陷，特殊人群场景 | Google Trends、消费者评论、Amazon 差评 | 痛点真实但不等于愿意换品牌 |
| **B 情绪与审美驱动型** | 哪些商品有悦己、礼赠与文化价值？ | 设计感、色彩、IP 与文化符号、短视频可传播性 | TikTok、抖音热点、灵感站 | 热度易复制，溢价不稳定 |
| **C 细分长尾赛道** | 哪些小众人群的高粘性需求没人做好？ | 异宠、小众运动、专业兴趣、垂直场景配件 | Google Trends 细分词、TikTok 垂类话题 | 规模天花板低，配件易被大厂顺手做 |
| **D 供应链红利与成本降维** | 哪条产业带能压出价格空间？ | 中国产业带成熟供给、可控质量、可复用工艺 | 1688、工厂官网、产业带报道 | 成本优势可能已被价格战吃掉 |

每条策略在界面上包含：策略编号、标题、一句话切入逻辑、三个标签（如“差评主题 / 产品缺陷 / 微创新”）、线索来源提示，以及当前是否被选中。

**策略不作为分类存储的唯一字段。** 候选同时保留策略 ID、策略编号与策略契合理由，详情页可回看“为什么是这条策略找到的”。

## 4. L2 流程层：六步落地流程

Agent 按固定顺序推进，每一步都有明确的数据源、产出和停等条件。流程导轨（flow rail）常驻界面，用四种状态显示进度。

| 步 | 名称 | Agent 做什么 | 主要数据源 | 产出 | V1 覆盖 |
|---|---|---|---|---|---|
| 1 | **发现需求** | 找上升需求、内容热度、反复出现的抱怨 | Google Trends 公开页面、TikTok、抖音、公开评论 | 需求线索与时间/地域标注 | 自动运行 |
| 2 | **验证市场** | 核对商品、价格带、竞品密度、评论痛点与市场空位 | Amazon.co.jp、乐天、Yahoo! Shopping 公开页面 | 市场初筛与竞争观察 | 自动运行 |
| 3 | **寻找货源** | 找中国供给线索，标注规格、MOQ、样品与交期待核项 | 1688、工厂、产业带、淘宝、京东 | 货源线索与待确认项 | 自动运行 |
| 4 | **利润核算** | 用可追溯价格与明确假设计算单件贡献利润 | 采购价、销售可购价、汇率、物流、平台费、广告、税费、退货 | 利润情景与敏感区间 | 需人填关键输入 |
| 5 | **小批量测试** | 规划样品与小批量验证，记录真实订单、转化率、退款率、净利润 | 真实订单与投放数据 | 测试结论与继续/停止建议 | 依赖真实数据与人的决定 |
| 6 | **扩大经营** | 供应链、库存、品牌与营销的扩张建议 | 供应商绩效、库存与现金数据 | 扩张方案与风险 | 依赖第 5 步结果 |

**流程状态机：**

- `completed` 有来源支撑，可继续下一步。
- `partial` 有线索但缺关键项（例如无竞品页面），停在原地等人补。
- `blocked` 数据不足，系统明确拒绝给结论（例如利润缺可购价）。
- `pending` 尚未开始。
- `current` 正在进行（运行中的阶段）。

**人在流程中的位置：** 第 1–3 步的结果由 Agent 产出、人审核；第 4 步的关键数字由人填；第 5 步是否下样由人决定；第 6 步的建议在第 5 步达标前不生成。

## 5. L3 证据层：数据源与访问边界

界面必须清楚区分“公开网页搜索线索”和“官方 API 已授权数据”，并按可信度排序使用：官方授权数据 > 获授权商业数据服务 > 公开网页搜索线索 > 用户提供材料。

平台分三种角色进入流程，每种角色的“能拿到什么”完全不同：

| 角色 | 平台 | 现在能拿到（公开搜索线索） | 需要授权才能拿到 |
|---|---|---|---|
| **需求与内容侧** | Google Trends | 公开页面上的相对热度线索、相关词 | 官方趋势序列（API） |
| | TikTok / Creative Center | 公开页面上的热门内容与话题线索 | 开放平台数据、账号与实时榜单 |
| | **抖音 / 快手** | 公开页面上的内容与话题线索 | 抖音开放平台应用与 scope；快手开放平台 / 磁力引擎资质与账号授权 |
| **销售市场侧** | Amazon.co.jp | 公开商品页面的标题、价格区间、评论主题 | SP-API 商品详情、站内搜索、热销榜、账号数据 |
| | 乐天 / Yahoo! Shopping | 同上 | 各平台官方 API |
| | Mercari Japan | 二手/个人定价线索 | 官方 API 或商业合作 |
| **货源侧** | 1688 | 公开供应页的规格与挂牌信息 | 开放平台搜索/详情/阶梯价、买家授权 |
| | **淘宝 / 天猫**、**京东**、**拼多多**、**义乌购 / 中国商品网** | 公开商品页、批发页的规格与挂牌价格 | 官方开放平台应用、主体资质、报价与 MOQ 权限 |

**边界：** 不模拟登录、不复用浏览器会话、不绕过验证码、不违反平台条款；搜索摘要不得被描述为销量、实时价格、平台热销榜或正式 MOQ 报价。

**平台角色可多选，且按市场归属。** 同一平台可以同时是销售与货源渠道：抖音/快手既给需求线索也开自己的店，淘宝/京东/拼多多既卖货也供货。目标市场（日本 / 中国 / 海外）决定哪些平台算“销售竞品”，采购来源国决定哪些平台算“货源”。因此同一条来源的角色随研究范围变化：淘宝页面在日本目标市场里记为国内货源对照，在中国目标市场里记为竞品。

**证据维度按平台实际角色与当前范围判定**，不按搜索式的意图判定；未登记平台的页面按搜索式阶段兜底并在备注中说明。

每条来源都保存：URL、标题、来源类型、采集日期、搜索式、原始摘要和所属候选。同一候选的结论必须能回到具体来源。

**来源按实际域名归属，不按搜索意图归属。** 搜索引擎把 `site:` 当提示而不是过滤，瞄准淘宝的搜索式可能返回 1688 页面。因此每条证据按 URL 实际域名判定平台，不属于已知平台的页面标记为“未匹配平台”，并在备注中说明搜索式原本针对哪个平台。

**货源平台的零售价不等于源头成本。** 淘宝、京东、拼多多、义乌购的公开页面多为零售或营销页，价格可用于价格带参考，不能据此断言供应商能力、MOQ 或利润；这类行在竞品分析里标记为“国内货源对照”，与目标市场竞品分开。

**经营者可选择货源平台。** 经营画像里的“优先货源平台”决定 Agent 规划哪些货源搜索式，默认包含 1688、淘宝、京东、拼多多与义乌购；取消勾选后对应平台不再进入货源检索。目标市场同样可切换（默认日本），切换后销售平台清单随之变化，经营画像会保留与新市场匹配的平台。

## 6. L4 决策层：人工审核门

候选卡直接承载审核动作，动作进入本地审核记录：

| 动作 | 含义 | 理由 |
|---|---|---|
| **继续研究** | 通过初审，进入下一轮补证 | 必填：下一步要补什么证据 |
| **暂缓** | 缺关键数据，先挂着 | 必填：缺哪一项 |
| **淘汰** | 不值得继续 | 必填：原因进入评估记录，用于改进下一轮发现 |

审核理由必须写下来（借鉴座舱测试 Agent 的“驳回必选原因”做法），理由与候选一起保存，并显示在候选卡上，避免同一类问题反复出现。

**四项独立判断：** 机会潜力、资源匹配度、风险水平、结论置信度。每项都要关联来源才可保存，不做加权总分。  
**利润模型：** 单件贡献利润 = 售价 − 采购成本（按手动汇率换算）− 头程 − 关税及进口税费 − FBA − 平台佣金 − 广告 − 退货预留 − 其他成本。缺任一必要输入即显示“待核验”，不让模型自行估算。

## 7. 三大任务模式

聊天框是主入口；模式决定的是“层 1 给谁看、谁去找商品”。

| 模式 | 层 1 的含义 | 人提供 | Agent 负责 | 典型产出 |
|---|---|---|---|---|
| **自动选品** | 四大策略卡，选一条即启动 | 策略 + 可选约束（市场、平台、人群、价格带） | 自主找货、筛候选、核验市场与货源 | 0–2 个待审候选 + 六步状态 + 来源 |
| **手动选品** | 研究范围卡（人给范围，Agent 出商品） | 商品名/链接，**或**人群、类目、市场、价格带等范围 | 对给定商品出评估；**或**在范围内自己挑出具体商品 | 评估结论，或范围内的具体商品 shortlist |
| **手动竞品分析** | 研究范围卡（对标研究） | 类目、目标市场、平台，或具体商品/品牌 | 盘点竞品集合、价格带、卖点与差评主题 | 竞品对照表、共性趋势、证据缺口 |

三种模式共用同一套对话、运行状态、来源与审核机制，区别只在于“谁定义要找什么”。常规主线不需要人先找商品。

## 8. 界面结构

```
顶栏   拾品 │ 模式切换（自动选品 / 手动选品 / 手动竞品分析） │ 搜索状态 · 模型
左栏   ① 选品策略 A–D（最高层级，可直接切换）
       最近会话
       数据源与运行 · 经营资源画像
       Agent 与数据源状态
主区   标题与新会话
       L1  策略卡 / 研究范围卡
       L2  六步流程导轨（含进行中与待补数据标记）
       L3  对话记录：Agent 运行进度、候选卡（策略契合、市场/货源初筛、来源）、竞品表
       输入区：市场与平台约束、快捷短语、发送
       L4  候选审核动作（继续 / 暂缓 / 淘汰 + 理由）、详情页四项判断与利润模型
```

**详情页标签：** 研究概览（Agent 判断、六步进度、市场与货源初筛）、Agent 任务、证据来源、利润模型、研究报告（可导出 Markdown）。

## 9. 功能需求

### P0 · 策略层

- 四个策略在左栏与主区同时可见，任一处切换立即生效。
- 策略卡显示编号、标题、切入逻辑、标签、线索来源与选中状态。
- 自动选品模式不要求输入商品名即可启动。
- 切换策略会写入运行记录，可回看这次用的是哪条策略。

### P0 · 流程层

- 六步导轨常驻，显示每步状态与当前推进到的步骤。
- 运行中显示百分比、阶段名与当前动作；刷新后恢复。
- 异常状态最终可结束（失败、无候选、需要人工审核），不留在无限运行。

### P0 · 对话与运行

- 三种模式在顶栏切换，会话绑定模式、策略/范围、运行 ID、消息与产物。
- 快捷短语点击后写入输入框，便于快速补充人群、价格带等约束。
- 运行中可继续追问；结果以卡片、表格与来源列表呈现。

### P0 · 自动选品与人工审核

- Agent 不要求商品名；自动产生 0–2 个有来源的优先候选。
- 候选必须引用真实返回的来源 ID；来源不足时允许返回 0 个候选。
- 候选卡分开展示策略契合、市场核验、货源核验、利润准备度、置信度与风险。
- 审核动作与理由写入记录，淘汰必须写原因。

### P0 · 手动选品

- 接受商品名、商品 URL、趋势/评论线索，或人群/类目/市场/价格带范围。
- 给范围时由 Agent 提出具体商品，而不是把范围原样退回给人。

### P0 · 手动竞品分析

- 支持指定类目、市场、平台、品牌或具体商品。
- 输出竞品集合、价格带线索、卖点与差评主题、未满足需求，每行保留来源与观察时间。
- 竞品不足或无法匹配时明确显示缺口，不推断市场份额。

### P0 · 证据、利润与风险

- 来源保存 URL、标题、搜索式、采集日期、摘要、来源类型与所属候选。
- 利润仅由人输入或可信报价进入确定性公式。
- 四项判断独立保存，需关联来源；无证据不打分。
- 同品价差结论需规格/包装匹配，否则阻止结论。
- 合规与知识产权为人工审查提醒，模型不担保可售。

### P1 · 平台连接器

- 分别设计 Google Trends、TikTok/抖音、Amazon JP/乐天/Yahoo 与 1688/淘宝/京东连接器。
- 每个连接器先确认官方产品、账户资格、API scope、地域、配额与展示条款，再实现。
- 合法数据服务与用户授权文件导入作为无通用搜索权限平台的替代路径。

### P1 · 小测与扩量

- 保存样品与采购预算、测试窗口、SKU、投放花费、订单、转化、退款、售后与单件净利。
- Agent 对照预设门槛给出继续/停止/调整建议。
- 任何下单、付款、刊登、补货都需要单独明确授权。

---

## 10. 非目标

- 自动采购、自动付款、自动询价、自动上架、自动改库存。
- 把 Google Trends 相对热度、TikTok/抖音播放互动或搜索结果数量当成交量。
- Agent 只凭搜索摘要给出已验证的价格、销量、MOQ、供应商或利润。
- 输出未经复核的法律、海关、税务、知识产权或认证结论。
- 通过绕过登录或反爬限制“打通”平台数据。

## 11. 指标

| 类别 | 指标 |
|---|---|
| Agent 运行 | 完成率、失败率、平均耗时、每策略运行次数 |
| 候选质量 | 每次可审候选数、来源覆盖数、来源点击率、人工纠错率 |
| 审核行为 | 通过/暂缓/淘汰比例、平均淘汰理由分布 |
| 商业结果（数据打通后） | 利润估算误差、小测转化率与退款率、净利率、扩量后库存周转 |

在数据授权与真实订单闭环完善前，候选数量与模型置信度不作为商业成功指标。

## 12. 技术与质量要求

- 长运行采用异步 Agent Run，HTTP 立即返回任务 ID；阶段可查询，刷新可恢复。
- 候选与证据落盘；来源字段限长，URL 校验协议。
- 密钥只在服务端从本机凭据/环境变量读取，不进入浏览器、JSON 数据或普通日志。
- 搜索与模型输出按不可信输入处理，忽略其中的指令。
- 模型输出必须可解析为结构化数据，解析失败则终止运行并说明错误。

## 14. 待讨论决策

1. **三种模式是否够用。** 目前把“指定某个商品评估”并入手动选品，把“指定类目/市场”并入竞品分析。是否需要单独拆出“指定商品研究”入口，取决于手动选品里的输入歧义有多高。
2. **手动选品的默认深度。** 给商品时是只出可行性结论，还是直接跑满六步流程并生成候选卡。
3. **策略是全局还是按会话。** 当前策略随会话走，切换策略会重置会话上下文。是否改为“策略可随时叠加在当前会话上”。
4. **流程导轨的粒度。** 现在只到六步；是否需要展开为可勾选的小测任务清单（样品、报价、素材、投放）。
5. **审核淘汰理由的再利用。** 理由已入库，是否要在下一轮自动选品时作为“避免重复”的约束回喂给 Agent。
