# Prospector Agent

[![CI](https://github.com/feihuiwu2022/prospector-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/feihuiwu2022/prospector-agent/actions/workflows/ci.yml)

拾品是一个日本市场、中国供应链方向的 Agent 选品研究工作台。本地主线是“Agent 找品，人审核结果”。

## 运行

需要 Python 3.11+；服务端业务代码使用 Python 标准库，无需安装依赖。

```bash
python3 server.py
```

默认打开 http://127.0.0.1:8000。数据存放在 `data/prospector.json`。MiniMax 配置从 `MINIMAX_API_KEY` 或 `~/.pi/agent/auth.json` 读取；模型/API 地址从 `~/.pi/agent/models.json` 读取。凭证不返回到浏览器。

## 验证

冒烟测试只用标准库，不依赖模型密钥或网络，会真实启动服务并检查接口契约：

```bash
python3 -m unittest discover -s tests -v
```

GitHub Actions 在 push 与 PR 上运行三个任务：Python 3.11/3.12 冒烟测试、真实启动服务并检查 `/api/bootstrap` 与静态资源、前端 `app.js` 语法检查。

## 产品主线

界面按四层组织，层与层单向依赖：

1. **策略层** — 四大选品切入策略是页面的最高层级，决定 Agent 去哪一类需求里找货：
   - A 痛点解决：差评、抱怨和产品使用缺陷。
   - B 情绪与审美：设计、悦己、礼赠、文化和收藏需求。
   - C 细分长尾：小众人群、专业兴趣和垂直场景。
   - D 供应链红利：产业带、工艺和源头成本优势。
2. **流程层** — 六步工作流：发现需求 → 验证市场 → 寻找货源 → 利润核算 → 小批量测试 → 扩大经营。当前自动运行覆盖公开网页发现、候选筛选以及市场/货源线索初筛；费用不完整时利润会标记为待核实，小测和扩量依赖真实经营数据与人的决策。
3. **证据层** — 每个结论带来源链接、采集时间与数据边界；公开网页搜索线索与官方 API 授权数据分开显示。
4. **决策层** — 人审核候选：继续研究 / 暂缓 / 淘汰，淘汰必须写原因；四项独立判断与利润模型保持分离。

聊天式工作台提供自动选品、手动选品、手动竞品分析和同品比价四种 Agent 模式。手动选品既可评估用户给出的商品/想法，也可在用户限定的人群、类目、市场或价格带内由 Agent 自主挑选；竞品分析针对指定类目或商品输出结构化对照；同品比价针对一个型号逐平台找公开报价，只对同配置机型比较差价，并把可比差价变成待填费用的候选。常规主线不要求人先找商品。

市场分国内（中国）与国际（日本、海外）两组：目标市场可设为中国做国内平台间差价，采购来源国也可设为日本/海外做国外货源进中国；跨币种差价不会自动给结论，因为页面里没有汇率、关税与头程，需要在候选里人工补齐这三项。

比价模式可勾选参与平台并临时指定采购来源国；比价结果能一键生成“价差研究”，用规格/包装匹配校验两侧商品，匹配不通过就不给价差结论；报告按店铺给出“谁更便宜、差多少”，并标出疑似促销页与“去除促销后的差价”，同时把本次差价与这对平台的历史差价中位数对照；每次运行的可见报价会写入本地价格观察记录，同一商品可以看到最近报价与较上次的变化。候选详情页用一套统一利润字段（售价/采购价各带币种）计算贡献利润，缺任何必要输入只显示“待核验”。经营画像里填一次“比价假设”（佣金率、广告、履约、退货预留，佣金率可按平台单独覆盖），比价报告就会直接给出每家卖出平台的单件贡献利润，并同时按「最低可见价 / 去促销最低价 / 同配置中位价」三种采购价基准各算一遍；利润模型还能填首批数量与回本周期，算出首批资金占用与每日需售出件数；候选里可以录入真实小测数据（窗口、投放、点击、订单、退款、销售额、净利润），系统按画像里的门槛（最少订单量、最高退款率、最低净利率）给出继续/停止/调整建议；达标后给出三档备货量与资金占用测算；六步流程的状态变化都会记入候选的时间线；侧栏还有「复盘小结」（处理过程统计）与「决策看板」按待决策/缺数据/可扩量分组，小测实测的广告成本与退款率可一键回灌利润假设；经营画像里可开启“把淘汰理由回喂给 Agent”，让下一轮自动选品避开你写明不要再来的一类；比价产生的候选还会带一份采购待办清单（起订量、书面报价、样品、验货、到岸成本等全部标为待确认），可逐项勾选，勾完自动推进六步流程的“寻找货源”；数据源页还有货源线索库，记录见过的页面与店铺，并可把店铺「标记货源」沉淀成带跟进状态与备注的货源档案；候选详情还能一键「扫描同品比价」；比价报告还可导出 Markdown。

## 采购与验证链路

比价只是起点，候选后面还有一整条由人确认的链路：

1. **店铺线索** — 比价时见过的页面与店铺按最近报价汇总，可在采购比价表里「标记货源」沉淀成货源档案（跟进状态 + 备注）。
2. **批量询价** — 一次向多家店铺生成询价单（含问题清单与回复截止日期），导出 Markdown 分发；卖家的书面答复（单价、MOQ、交期、发票）逐条录回，状态从「待发送」到「回收中」到「已齐」，回复率进复盘。
3. **供应商比较** — 并排比较各家书面报价：单价、MOQ、首单资金占用（与预算对照）、交期、发票，标出书面最低价、最小起订量、最快交期。
4. **采购单草案** — 从比较表生成草案（金额、预计到货日），状态由你手工记录：草案 → 已下单 → 已发货 → 已收货；到货后自动生成「录入实际到货成本」待办。系统不联系卖家、不付款、不发货。
5. **实际到货与验货** — 到货后录入实收数量、实际单价、运费、关税、保险与破损比例，系统摊薄出每件到岸成本并回填利润模型；验货清单按品类给出（电子/家居/宠物/服饰/美妆/通用）；验货异常（短装/破损/错发）会减少可售数量、赔付从成本里扣掉，每件到岸成本自动重算，并生成索赔待办。
6. **书面报价回填** — 一键把卖家书面价回填为利润模型的采购价，并写成一条来源证据，利润因此可回溯到「谁说了什么、什么时候说的」。
7. **真实小测** — 录入窗口、投放、点击、订单、退款、销售额、净利润，按画像门槛给出继续/停止/调整；实测的广告成本与退款率可一键回灌利润假设。
8. **扩量测算** — 小测达标后给出 30/45/60 天三档备货量、安全库存与资金占用，并与预算对照；六步流程的状态变化都记入候选时间线。

每一步都保留来源、状态与人工确认点；缺数据就停在原地，不用零值或推测填补。

## 数据源边界

MiniMax Web Search 通过官方 MCP 搜索公开页面并保留来源链接。它不等于 Google Trends 原始趋势 API、TikTok/抖音实时榜、Amazon 商品 API 或 1688 正式报价。Amazon、乐天、Yahoo、1688、淘宝、京东的具体商品数据需对应官方 API/商业授权或页面人工复核；系统不模拟登录或绕过访问控制。完整边界见[数据源与运行页](public/index.html)、[PRD](docs/PRD.md)和[架构文档](docs/ARCHITECTURE.md)。

平台登记表是唯一事实来源：每个平台标注角色（需求 / 销售 / 货源，可多选）、销售市场与供给市场。经营画像里的目标市场决定 Agent 去哪些销售平台核对竞品，采购来源国决定它去找哪些货源页面；同一平台在不同市场里的证据角色随之改变（淘宝在日本目标市场里是货源对照，在中国目标市场里是竞品）。

候选详情保留来源、Agent 初筛和六阶段状态。利润使用确定性公式；四项评分各自展示，不合并成总分。Agent 结果均待人工审核，不会下单或付款。
